    IMPORTANT — Clerk JWT template prerequisite: The middleware reads `sessionClaims.role`, which requires a custom JWT template in the Clerk Dashboard. Without this, `sessionClaims.role` will always be `undefined` and role routing will silently fail. After creating `src/middleware.ts`, add a comment block at the top of the file documenting the required Clerk Dashboard configuration:

    ```
    // REQUIRED: Clerk Dashboard > Sessions > Edit JWT template
    // Add custom claim: { "role": "{{user.public_metadata.role}}" }
    // Without this, sessionClaims.role is undefined and role-based routing fails silently.
    ```

    Also add a `CLERK_JWT_TEMPLATE_CONFIGURED` placeholder to `.env.example` (as a reminder, not a real env var):
    ```
    # MANUAL STEP: In Clerk Dashboard > Sessions > Edit JWT template,
    # add claim: { "role": "{{user.public_metadata.role}}" }
    # Role-based routing will not work until this is done.
    ```

    5. Create `src/lib/auth.ts` — helper function `setUserRole(userId: string, role: UserRole)` that calls `clerkClient.users.updateUser()` to set `publicMetadata.role`. Export as a server action ("use server"). Import UserRole from `@/types`.

    6. Create `src/db/index.ts` — Drizzle singleton pattern per research Pattern 2. Use `postgres` driver with `prepare: false` for Supabase Transaction pooler compatibility. Export `db` instance.

    7. Create `src/db/schema.ts` — define `userRoleEnum` pgEnum ("buyer", "seller") and `users` pgTable with: id (text, primary key — Clerk user ID), email (text, unique, not null), role (userRoleEnum, default "buyer"), createdAt (timestamp, defaultNow), updatedAt (timestamp, defaultNow).

    8. Create `drizzle.config.ts` — point schema to `./src/db/schema.ts`, out to `./src/db/migrations`, dialect postgresql, dbCredentials from DATABASE_URL env var.
