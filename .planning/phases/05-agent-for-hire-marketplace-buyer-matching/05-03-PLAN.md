  <behavior>
    - recordBuyerEvent({ userId, eventType, listingId, metadata }) inserts a row into buyerEvents
    - recordBuyerEvent validates eventType is one of: listing_viewed, listing_saved, search_executed
    - buildPreferenceSummary(events) returns a text string like "3 bedroom single family $300k-$450k Phoenix AZ"
    - buildPreferenceSummary uses ONLY objective property features: price range, bed count, bath count, sqft, property type, city/zip — NO school ratings, walkability, or neighborhood scores (Fair Housing)
    - buildPreferenceSummary returns null if fewer than 3 events (insufficient data)
    - getRecommendations(userId) generates preference embedding, queries pgvector for top 10 similar active listings, returns NormalizedListing[]
    - getRecommendations excludes listings the user has already saved
    - POST /api/buyer-events validates body and calls recordBuyerEvent
  </behavior>
  <action>
    1. Create src/services/matching/buyer-events.ts:
       - recordBuyerEvent({ userId, eventType, listingId?, metadata? }): Validate eventType against allowed set ('listing_viewed'|'listing_saved'|'search_executed'), insert into buyerEvents with nanoid() for ID, return inserted row.
       - getRecentEvents(userId, days=90): SELECT from buyerEvents WHERE userId AND occurredAt > now() - interval days, ORDER BY occurredAt DESC.

    2. Create src/services/matching/preference-profile.ts:
       - buildPreferenceSummary(events: BuyerEvent[]): Aggregates events into a text description.
         - For listing_viewed/listing_saved events: look up the listing's price, beds, baths, sqft, propertyType, city, state from the listings table (batch query by listingId).
         - For search_executed events: extract filters from metadata JSON.
         - Compute: price range (min-max of viewed/saved), modal bedroom count, modal property type, most frequent city/state.
         - Return formatted string: "{beds} bedroom {propertyType} ${minPrice/100}k-${maxPrice/100}k {city} {state}"
         - CRITICAL: Do NOT include school quality, walkability, neighborhood scores, or any demographic proxy. Fair Housing Act compliance.
         - Return null if < 3 events.

    3. Create src/services/matching/listing-recommendations.ts:
       - getRecommendations(userId):
         a) Call getRecentEvents(userId) to get trailing 90-day events.
         b) Call buildPreferenceSummary(events) — if null, return empty array.
         c) Generate embedding via OpenAI: `openai.embeddings.create({ model: 'text-embedding-3-small', input: summary })`.
         d) Query pgvector via raw SQL:
            ```sql
            SELECT id, street_address, city, state, zip, price, bedrooms, bathrooms, sqft, property_type, status, created_at,
                   (embedding <=> $1::vector) AS distance
            FROM listings
            WHERE status = 'active' AND embedding IS NOT NULL
              AND id NOT IN (SELECT listing_id FROM buyer_events WHERE user_id = $2 AND event_type = 'listing_saved' AND listing_id IS NOT NULL)
            ORDER BY distance ASC LIMIT 10
            ```
         e) Normalize results to NormalizedListing[] and return.

    4. Create src/app/api/buyer-events/route.ts:
       - POST: Auth required (Clerk auth()). Parse body with zod: { eventType: z.enum(['listing_viewed','listing_saved','search_executed']), listingId: z.string().optional(), metadata: z.record(z.unknown()).optional() }. Call recordBuyerEvent. Return 201 { ok: true }.
  </action>
