Build the RESO Web API direct integration layer that replaces SimplyRETS middleware for high-volume MLS boards.

Purpose: MLS-04 requires coverage of top 10-15 highest-volume markets. Direct RESO Web API integration provides faster data freshness (delta sync vs. nightly batch), lower per-query cost, and eliminates middleware dependency for boards where a direct IDX agreement exists.

Output: RESO client service, normalizer, delta sync Inngest cron, resoBoards config table, and mlsListings extended to track RESO sources.

    - fetchResoListings(boardConfig, params) returns array of raw RESO Property resources
    - fetchResoDelta(boardConfig, sinceTimestamp) appends $filter=ModificationTimestamp gt {sinceTimestamp} to OData query
    - RESO client sends Authorization: Bearer {boardConfig.apiToken} header
    - RESO client follows @odata.nextLink for pagination (handles multi-page responses)
    - normalizeResoListing maps RESO Data Dictionary 2.0 fields (ListPrice, BedroomsTotal, BathroomsTotalDecimal, LivingArea, PropertyType, StandardStatus, Latitude, Longitude, Media[].MediaURL) to NormalizedListing
    - RESO prices are in dollars; normalizer converts to cents (multiply by 100) for internal consistency (same pattern as SimplyRETS — see Phase 3 decision)
    - normalizeResoListing sets source: "mls" on output
  </behavior>
  <action>
    Create src/services/mls/reso-client.ts:
    - Export interface ResoBoardConfig { boardId: string; apiUrl: string; apiToken: string; name: string; }
    - Export async function fetchResoListings(board: ResoBoardConfig, params?: { filter?: string; top?: number; skip?: number }): Promise<ResoProperty[]>
    - Makes GET request to board.apiUrl + "/Property" with OData query params ($filter, $top, $skip, $select, $expand=Media)
    - Follows @odata.nextLink recursively until no more pages (cap at 10 pages per sync to prevent runaway)
    - Export async function fetchResoDelta(board: ResoBoardConfig, since: Date): Promise<ResoProperty[]>
    - Calls fetchResoListings with $filter=ModificationTimestamp gt {since.toISOString()}
    - Use native fetch (not axios) — consistent with codebase pattern

    - Export interface ResoProperty with RESO Data Dictionary 2.0 field names (ListingKey, ListPrice, BedroomsTotal, BathroomsTotalDecimal, LivingArea, PostalCity, StateOrProvince, PostalCode, UnparsedAddress, PropertyType, StandardStatus, Latitude, Longitude, ModificationTimestamp, Media?: Array<{ MediaURL: string }>)
    - Export function normalizeResoListing(raw: ResoProperty, boardId: string): maps to the shape needed for mlsListings upsert
    - Price conversion: raw.ListPrice (dollars) * 100 = cents
    - photoUrls: extract from raw.Media array, take first 20 MediaURL values
    - mlsSource: "reso:{boardId}" to distinguish from "simplyrets"
