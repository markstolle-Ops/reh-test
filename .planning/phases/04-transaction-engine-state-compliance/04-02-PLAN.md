       - Requires auth (Clerk `auth()` — same pattern as existing listing routes)
       - Accepts JSON body: { listingId, offerPriceCents }
       - Looks up listing to get sellerUserId and propertyState
       - Calls createTransaction with buyerUserId from auth
       - Returns 201 with transaction object

    2. `GET /api/transactions` route:
       - Requires auth
       - Returns all transactions where user is buyer OR seller
       - Includes currentStatus, listingId, offerPriceCents, createdAt

    3. `GET /api/transactions/[id]` route:
       - Requires auth
       - Returns full transaction with events array (ordered by occurredAt ASC)
       - Returns 403 if user is not buyer or seller on this transaction

    4. `POST /api/transactions/[id]/events` route:
       - Requires auth
       - Accepts JSON body: { eventType, payload }
       - Validates eventType against TransactionEventType
       - Calls appendTransactionEvent
       - Returns 201

    Follow existing API route patterns in the codebase (auth check via `auth()`, JSON responses, error handling).
